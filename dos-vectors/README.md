# CompleXML — Replication Package

Minimal code to reproduce the paper's key findings: (1) four post-parse
algorithmic-complexity sinks in libxml2 are super-linear on plain, well-formed XML
(micro-benchmarks), and (2) they are weaponizable, pre-authentication, against
mainstream SAML software (end-to-end harness).

> **Scope / safety.** Every attack here targets *local Docker containers you bring
> up yourself*. `fire.py` refuses non-loopback hosts by design. Do not point it at
> anything you do not own.

---

## What is included vs. left out

**Included (this directory):**

| File(s) | Role | Tier |
|---|---|---|
| `saml_payloadgen.py` | the one payload generator used by *everything* | **core** |
| `bench.py`, `plot.py` | micro-benchmarks + their figures (§3) | **core** |
| `recon_bench.c` | the C7 (Wreckoncile) `importNode` sink, called by `bench.py` | **core** |
| `run_target.sh` | brings each SAML target up/down on a fixed box | **core** |
| `fire.py` | builds a payload and fires it + liveness probe | **core** |
| `bench_harness.py` | orchestrates run→fire→measure across all targets (§4) | **core** |
| `plot_heatmap.py` | the comparability heatmap (Fig. 7) | **core** |
| `targets/` | build contexts for the 3 *custom-built* targets (SSP ×2, Authentic2) | **core** |
| `goparse.go`, `XercesBench.java`, `EngineBench.java`, `SantuarioBench.java`, `.santuario_cp*` | cross-engine comparison curves (Expat/Xerces/Go/Santuario overlays) | optional |
| `cgbench.c` | callgrind profiles that pin each sink's complexity class (taxonomy) | optional |
| `sample_data/harness_results.csv` | one finished run, so the heatmap builds without a 2 h measurement | data |

**Left out of the replication package on purpose** (not needed to reproduce findings):

- `paper/` — the LaTeX source.
- `harness_runs/`, `json_archive/`, `plots/` — generated outputs; regenerated by the steps below.
- `*.class`, `__pycache__/` — build artifacts; recompiled.
- `REPORT.md`, `CODE_AUDIT.md`, `DISCLOSURE.md`, `dos_experiment_results.txt` — internal notes/logs.
- `stack*.dot` — a Graphviz architecture diagram, not a measurement.

**If you want the truly minimal subset** (end-to-end SAML DoS only, no cross-engine
figures): `saml_payloadgen.py`, `run_target.sh`, `fire.py`, `bench_harness.py`,
`plot_heatmap.py`, and `targets/`. Everything else supports §3's engine/figure work.

## Prerequisites

- **Docker** (targets run as containers; official images are pulled on first use).
- **Python 3.10+** with `lxml`, `numpy`, `matplotlib` (`uv pip install lxml numpy matplotlib`).
- **libxml2 CLI tools**: `xmllint`, `xmlsec1` (Debian/Ubuntu: `apt-get install libxml2-utils xmlsec1`).
- **C toolchain + libxml2 headers** for `recon_bench.c` (`apt-get install build-essential libxml2-dev`).
- *(optional, cross-engine)* `go`, a JDK (`javac`/`java`), and Xerces/Santuario jars;
  `cgbench.c` additionally needs `valgrind` + `valgrind-dev`.

A note on libxml2 version: `bench.py` times libxml2 **through `lxml`**, so you are
measuring whatever libxml2 your `lxml` is linked against. Report that version
(`python3 -c "import lxml.etree; print(lxml.etree.LIBXML_VERSION)"`); the paper's
"current libxml2" curves were taken on 2.14.x/2.15.x, where the post-parse sinks
are unfixed.

## (a) Individual targets

Ten target stacks: `nextcloud gitlab synapse ssp-sp ssp-idp authentic2 drupal
wordpress moodle authentik` (SSP and Authentic2 each expose an IdP *and* an SP
role to `fire.py`).

```bash
./run_target.sh list                      # names + ports + probe paths
SIZE=medium ./run_target.sh up wordpress  # bring one up on the fixed 8 vCPU / 16 GB box
./run_target.sh probe wordpress           # confirm it serves
# fire a single request and watch the hold:
python3 fire.py --target wordpress --vector C14N1D3 --size 2400 --probe
./run_target.sh down wordpress            # (or: down all)
```

`SIZE=small` (4 vCPU / 8 GB) and `SIZE=medium` (8 vCPU / 16 GB) set the container
CPU/RAM caps; omit `SIZE` for the host's full core count (unconstrained). `fire.py
--vector` accepts the paper names (`FlAttr`, `C14N1D3`, `XPlode`, `Wreckoncile`)
and the low-level tokens (`attr`, `c14n-inc`, `c14n-exc`, `xpath`, `reconcile`);
`--dry-run` prints the payload size without sending.

## (b) Micro-benchmarks (§3 cost curves)

```bash
# one-time: build the C7 sink binary bench.py calls
cc -O2 recon_bench.c -o /tmp/recon_bench_214 $(pkg-config --cflags --libs libxml-2.0)

python3 bench.py                 # all vectors, default size sweeps -> stdout table
python3 plot.py                  # -> plots/<vector>.png  (one figure per vector)
python3 plot.py flattr,c14n-inc  # just these
```

Vectors: `flattr` (FlAttr/C5), `c14n-inc` + `c14n-exc` (C14N1D3/C2,C1),
`xpath` (XPlode/C3), `reconcile` (Wreckoncile/C7).

*Cross-engine overlays (optional)* — compile the other engines and point `bench.py`
at them (it looks for `/tmp/recon_bench_214`, `/tmp/goparse`, `/tmp/xercesImpl-*.jar`):

```bash
go build -o /tmp/goparse goparse.go
javac XercesBench.java EngineBench.java
javac -cp "$(cat .santuario_cp)" SantuarioBench.java     # edit .santuario_cp to your jar paths
```

*Complexity-class profiling (optional)*: `cgbench.c` under `valgrind
--tool=callgrind --collect-atstart=no` isolates each sink.

## (c) Test harness (§4 comparable measurement)

Drives `run_target.sh` (up/verify/down) and `fire.py` (fire + probe) across every
target on one fixed box, and writes the comparable metric
(`unavailable_s / attacker_byte`) per (target, vector) cell.

```bash
python3 bench_harness.py --list                                  # plan: stacks, pools, in-flight
python3 bench_harness.py --targets wordpress,synapse --box medium  # a subset
python3 bench_harness.py --all --box medium --repeats 3          # the full paper run
```

Output: per-cell JSON under `harness_runs/` plus an aggregate
`harness_runs/harness_results.csv`. `--dry-run` prints the plan without firing.
Each target is driven at a load matched to its concurrency model (see
`bench_harness.py` `TARGETS`); a full `--all` run takes ~1–2 h.

## (d) Graph generation

```bash
# the comparability heatmap (Fig. 7) — from your run, or the bundled sample:
python3 plot_heatmap.py harness_runs/harness_results.csv
python3 plot_heatmap.py sample_data/harness_results.csv     # no measurement needed
# -> heatmap_time_per_byte.pdf (+ .png).  Colour = s / attacker KB (log scale).

# the §3 cost curves:  python3 plot.py          -> plots/<vector>.png
```

`plot_heatmap.py` also accepts a *directory* of per-cell `*.attack.*.json` instead
of a CSV, to build the figure from mixed runs.
